# 研究工作区与项目管理

以减少重复信息为原则。优先使用项目仓库中的既有文档和 Git 历史，只保留一个
工作区级项目总览，不建立与项目仓库并行的管理体系。

## 项目的判定

项目是围绕相对独立的目标或可交付成果、需要持续推进的工作单元，可以是科学研究、
工程实现或产品化系统。目录中是否包含代码、代码能否复用，都不能单独决定其类别；
应根据该目录在当前工作区中的实际用途判断。

不要因为一个项目包含通用代码，就将其误归类为工具。参考仓库用于提供外部实现或
方法依据，工具用于支持其他项目完成工作，两者均不承担当前工作区中的独立目标。

## 目录约定

只创建当前确有内容的类别：

```text
projects/                 在研项目仓库
references/repos/         上游仓库或参考仓库
references/code/          代码快照与示例
datasets/                 独立管理的数据集（如有）
tools/                    支撑性工具
docs/INDEX.md             工作区项目总览
results/                  运行输出与日志
.agents/skills/           工作区技能
archive/                  已确认停止维护的材料（按需）
```

项目自身的 `README.md` 和既有文档是项目基础信息与技术事实的权威来源。项目名称、目标与范围、
主要入口、结果位置等稳定信息应优先写在项目 `README.md` 中；已有等价内容时不要
另加元数据块。仅当程序确实需要读取结构化信息时，才增加最小化的 `project.yaml`。

优先级、当前问题、阻塞项和下一检查点等动态信息只保存在 `docs/INDEX.md`，不要在
项目仓库之外复制其 `README.md`、路线图、结论或决策记录。

## 工作流程

1. 阅读工作区和相关仓库中的 `AGENTS.md`、`CLAUDE.md` 等约束。
2. 检查现有目录、Git 仓库、项目文档和结果路径，先识别已有目标与记录。
3. 按实际用途区分项目、参考仓库、参考代码、数据集、工具、技能、结果和非活跃材料；
   不重复登记同一目标。
4. 移动目录前检查未提交修改、嵌套仓库、符号链接和路径引用。只有用户要求整理时才
   移动，并保持仓库边界和变更的可恢复性。
5. 仅在新建工作区总览或项目状态发生变化时，维护 `docs/INDEX.md`；每个在研项目只占一行，
   字段限于：优先级、项目、阶段、当前问题、当前运行、阻塞项、下一检查点。
6. 使用 Git 检查变更并保存历史；未经用户要求不要提交。

具体训练、评测和运行记录交由 `research-experiment`；具有长期复用价值的设计、调查
和知识文档交由 `research-docs`。

## 复查与清理

只有在新证据改变项目问题、优先级、阻塞项或下一步时，才更新项目总览。暂停、结束
或归档项目，应以现有证据或用户的明确决定为依据。

默认不创建 `projects.yaml`、多级实验组织结构、实验登记表、项目管理副本或人为量化评分，
也不为单纯记录活动而写文档。保留有解释价值的失败记录和不可替代的证据。删除任何
材料前，必须列明具体目标并取得用户明确同意。
